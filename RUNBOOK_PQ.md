# PQ Devnet Runbook

Post-quantum (ML-DSA-44) local devnet — setup, benchmark, and teardown.

**Branch:** `post_quantum_dev` (bsc) / local branch (node-deploy)  
**Chain ID:** 714 | **Validators:** 4 | **Block time:** 3 s

## Step 2 — Generate PQ account

Run once. The `-seed` flag makes the output deterministic — same seed always
produces the same address, so the address can be hard-coded in scripts.

```bash
cd ~/Workspace/node-deploy/tools/gen-pq-account
go build .
cd ~/Workspace/node-deploy

./tools/gen-pq-account/gen-pq-account \
  -seed deadbeef00112233 \
  -out keys/pq_account

cat keys/pq_account/address.txt   # e.g. 0xABCD...1234
```

Files written:
- `keys/pq_account/address.txt`  — sender address (0x…)
- `keys/pq_account/pubkey.hex`   — 1312-byte ML-DSA-44 public key
- `keys/pq_account/privkey.hex`  — 2592-byte private key (**keep secret**)

> Re-running with the same `-seed` is safe — it always produces the same keys.

## Step 3 — Start the devnet

```bash
cd ~/Workspace/node-deploy

# Full reset: wipe state, regenerate genesis, init nodes, start validators
bash bsc_cluster.sh reset
```

This will:
1. Copy validator & BLS keys to `.local/`
2. Run the Python genesis generator (requires Poetry + Forge)
3. `geth init` each validator with the generated genesis
4. Start 4 validator processes
5. Call `create-validator` to register validators on StakeHub

Fork activation note:
- `PQ` is activated by the `--override.pqhardfork` timestamp override.
- In both `bsc_cluster.sh` and `bsc_fullnode.sh`, it is wired to `LastHardforkTime`, the same late-fork timestamp used for `Pasteur`.

Wait ~30 s for the chain to produce blocks:

```bash
# Confirm blocks are being produced
curl -s http://127.0.0.1:8545 \
  -X POST -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}' \
  | jq -r '.result' | xargs printf "Block: %d\n"
```

Check INIT_HOLDER balance (should be ~500 M BNB):

```bash
curl -s http://127.0.0.1:8545 \
  -X POST -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_getBalance","params":["0x04d63aBCd2b9b1baa327f2Dda0f873F197ccd186","latest"],"id":1}' \
  | jq -r '.result'
```

## Step 6 — Run PQ benchmark

`txpq` handles everything automatically:
1. Checks PQ address balance → funds from INIT_HOLDER if needed (default 10 BNB)
2. Checks registry → registers pubkey via delegate-register if needed
3. Starts sending PQ transactions and prints live stats

```bash
cd ~/Workspace/node-deploy

./txpq/txpq \
  -endpoint  http://127.0.0.1:8545 \
  -chainId   714 \
  -keyfile   keys/pq_account/privkey.hex \
  -workers   1 \
  -interval  200ms \
  -duration  60s \
  2>&1 | tee /tmp/pq_1worker.log
```

## Step 7 — Scale up workers to find TPS ceiling

Repeat with increasing `-workers` until block propagation degrades or errors appear:

```bash
for W in 1 2 4 8 16; do
  echo "=== workers=$W ==="
  ./txpq/txpq \
    -endpoint http://127.0.0.1:8545 \
    -chainId  714 \
    -keyfile  keys/pq_account/privkey.hex \
    -workers  $W \
    -interval 50ms \
    -duration 60s \
    -fund     0 \         # already funded from step 6
    2>&1 | tee /tmp/pq_w${W}.log

  sleep 10   # let mempool drain
done
```

Extract peak TPS per run:

```bash
for W in 1 2 4 8 16; do
  PEAK=$(grep "\[stats\]" /tmp/pq_w${W}.log | awk '{print $5}' | sort -n | tail -1)
  echo "workers=$W  peak_tps=$PEAK"
done
```

## Step 8 — Measure block propagation impact

While `txpq` is running, watch block times from a second terminal:

```bash
watch -n 3 'curl -s http://127.0.0.1:8545 \
  -X POST -H "Content-Type: application/json" \
  -d "{\"jsonrpc\":\"2.0\",\"method\":\"eth_getBlockByNumber\",\"params\":[\"latest\",false],\"id\":1}" \
  | jq "{number: .result.number, timestamp: .result.timestamp, size: .result.size}"'
```

Target: block propagation < 0.45 s (3 s slot × 15 % budget).  
Estimated max block payload at 0.45 s propagation on 100 Mbps LAN:

```
0.45 s × 100 Mbps / 8 = ~5.6 MB per block
PQ tx size ≈ 2440 bytes (From 20B + Sig 2420B + overhead ~100B)
Max PQ txs per block ≈ 5.6 MB / 2440 B ≈ 2295 txs
At 3 s blocks → TPS ceiling ≈ 765 TPS
```

Record at what `-workers` / `-interval` setting the chain starts missing slots or
block timestamps drift beyond 3.5 s.

## Operational Commands

```bash
# Stop all validators
bash bsc_cluster.sh stop

# Restart a single validator (e.g. index 0)
bash bsc_cluster.sh restart 0

# Wipe and restart everything
bash bsc_cluster.sh reset

# Tail validator 0 logs
tail -f .local/validator0/bsc.log

# Check each validator's block height
for PORT in 8545 8547 8549 8551; do
  H=$(curl -s http://127.0.0.1:$PORT \
    -X POST -H "Content-Type: application/json" \
    -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}' \
    | jq -r '.result // "err"')
  printf "port=%d  block=%d\n" $PORT $((H))
done

# Check PQ registry for an address
ADDR="0xABCD...1234"
curl -s http://127.0.0.1:8545 \
  -X POST -H "Content-Type: application/json" \
  -d "{\"jsonrpc\":\"2.0\",\"method\":\"eth_call\",\"params\":[{\"to\":\"0x0000000000000000000000000000000000000070\",\"data\":\"${ADDR}\"},\"latest\"],\"id\":1}" \
  | jq -r '.result' | wc -c   # should be 2626 (= 1312 bytes hex + 2 for 0x prefix)
```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `sender not registered` error in node log | `pqRegistryBackend` nil or cache cold | Ensure geth was built from `post_quantum_dev`; restart node after registration tx confirms |
| txpq exits with `registration tx not mined within 60s` | Chain not producing blocks | Check `bsc_cluster.sh reset` completed; check validator logs |
| `already registered with a different pubkey` | Key file changed after first run | Use same `-seed` value; or wipe devnet and restart |
| All txpq sends fail with `nonce too low` | Multiple workers sharing nonce state | Reduce `-workers`; nonces are striped by worker ID |
| Block timestamp drift > 3.5 s | TPS ceiling hit | Record this `-workers` value as the ceiling data point |
