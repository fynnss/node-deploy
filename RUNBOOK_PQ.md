# PQ Devnet Runbook

Post-quantum (ML-DSA-44) local devnet — setup, benchmark, and teardown.

**Branch:** `post_quantum_dev` (bsc & node-deploy)  
**Chain ID:** 714 | **Validators:** 4 | **Block interval:** 450 ms

**PQ voting:** Validators use ML-DSA-44 signatures (via `--pqvotekey`) instead of
BLS for vote attestation. Votes are aggregated into STARK proofs in block headers.

## Step 2 — Generate PQ account

Run once. The `-seed` flag makes the output deterministic — same seed always
produces the same address, so the address can be hard-coded in scripts.

```bash
cd ~/Workspace/node-deploy/tools/gen-pq-account
go build .
cd ~/Workspace/node-deploy

./tools/gen-pq-account/gen-pq-account \
  -seed deadbeef00112233 \
  -out keys/pq_account

cat keys/pq_account/address.txt   # e.g. 0xABCD...1234
```

Files written:

- `keys/pq_account/address.txt` — sender address (0x…)
- `keys/pq_account/pubkey.hex` — 1312-byte ML-DSA-44 public key (hex)
- `keys/pq_account/privkey.hex` — 2560-byte private key (hex, **keep secret**)
- `keys/pq_account/pubkey.bin` — raw binary pubkey (for geth / registry)
- `keys/pq_account/privkey.bin` — raw binary privkey (consumed by `--pqvotekey`)

> Re-running with the same `-seed` is safe — it always produces the same keys.

## Step 3 — Start the devnet

```bash
cd ~/Workspace/node-deploy

# Full reset: wipe state, regenerate genesis, init nodes, start validators
bash bsc_cluster.sh reset
```

This will:

1. Copy validator & BLS keys to `.local/`
2. Generate per-validator ML-DSA-44 keys (deterministic seeds: `pq-validator-{0..3}`)
3. Run the Python genesis generator (requires Poetry + Forge)
4. Inject PQ pubkeys into genesis via `inject_pq_genesis.py` (pre-populates 0x70 storage)
5. `geth init` each validator with the generated genesis
6. Start 4 validator processes with `--pqvotekey <datadir>/pq/privkey.bin`
7. Call `create-validator` to register validators on StakeHub

Fork activation note:

- `PQ` is activated by the `--override.pqhardfork` timestamp override.
- In both `bsc_cluster.sh` and `bsc_fullnode.sh`, it is wired to `LastHardforkTime`, the same late-fork timestamp used for `Pasteur`.

PQ voting flow:

- Each validator's PQ pubkey is pre-registered at `0x70` (pqKeyRegistry) in genesis state
- At startup, `WarmPQRegistryCache` reads pubkeys from state trie into in-memory cache
- Validators sign votes with ML-DSA-44 (via `--pqvotekey`), replacing BLS `--vote`
- The block sealer aggregates PQ vote signatures into a STARK proof in the block header

Wait ~30 s for the chain to produce blocks:

```bash
# Confirm blocks are being produced
curl -s http://127.0.0.1:8545 \
  -X POST -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}' \
  | jq -r '.result' | xargs printf "Block: %d\n"
```

Check INIT_HOLDER balance (should be ~500 M BNB):

```bash
curl -s http://127.0.0.1:8545 \
  -X POST -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_getBalance","params":["0x04d63aBCd2b9b1baa327f2Dda0f873F197ccd186","latest"],"id":1}' \
  | jq -r '.result'
```

Verify PQ voting is active:

```bash
# All 4 validators should produce PQ votes
for i in 0 1 2 3; do
  echo "node$i PQ votes: $(grep -c 'PQ vote produced' .local/node$i/bsc.log)"
done

# STARK attestation assembled (on sealer) — votes should be 3 or 4
grep "STARK attestation assembled" .local/node0/bsc.log | tail -3

# STARK attestation verified (on non-sealers)
grep "STARK attestation verified" .local/node1/bsc.log | tail -3

# No "not an active validator" errors
grep -c "not an active" .local/node{0,1,2,3}/bsc.log
```

## Step 7 — Scale up workers to find TPS ceiling

Repeat with increasing `-workers` until block propagation degrades or errors appear:

```bash
for W in 1 2 4 8 16; do
  echo "=== workers=$W ==="
  ./txpq/txpq \
    -endpoint http://127.0.0.1:8545 \
    -chainId  714 \
    -keyfile  keys/pq_account/privkey.hex \
    -workers  $W \
    -interval 50ms \
    -duration 60s \
    -fund     0 \
    2>&1 | tee /tmp/pq_w${W}.log
  # -fund 0: skip re-funding, already funded from step 6

  sleep 10   # let mempool drain
done
```

Extract peak TPS per run:

```bash
for W in 1 2 4 8 16; do
  PEAK=$(grep "\[stats\]" /tmp/pq_w${W}.log | grep -oP 'tps=\K[0-9.]+' | sort -n | tail -1)
  echo "workers=$W  peak_tps=$PEAK"
done
```

## Step 8 — Measure block propagation impact

While `txpq` is running, watch block times from a second terminal:

```bash
watch -n 1 'curl -s http://127.0.0.1:8545 \
  -X POST -H "Content-Type: application/json" \
  -d "{\"jsonrpc\":\"2.0\",\"method\":\"eth_getBlockByNumber\",\"params\":[\"latest\",false],\"id\":1}" \
  | jq "{number: .result.number, timestamp: .result.timestamp, size: .result.size}"'
```

Block interval in this devnet is **450 ms**. Estimated max block payload at
0.45 s propagation on 100 Mbps LAN:

```
0.45 s × 100 Mbps / 8 = ~5.6 MB per block
PQ tx size ≈ 2489 bytes (Sig 2420B + other fields ~69B)
Max PQ txs per block ≈ 5.6 MB / 2489 B ≈ 2249 txs
At 450 ms blocks → TPS ceiling ≈ 4998 TPS
```

Record at what `-workers` / `-interval` setting the chain starts missing slots or
block timestamps drift beyond 500 ms.

## Step 9 — Compare results

Benchmark run: 10 workers, 50 ms interval, 60 s duration (≈ 200 TPS target), chain ID 714, 450 ms block interval.

| Metric                            | secp256k1 baseline | ML-DSA-44 PQ             | Ratio     |
| --------------------------------- | ------------------ | ------------------------ | --------- |
| Tx wire size                      | ~106 B             | ~2,489 B                 | **23.5×** |
| Avg block size (user txs)         | ~10,814 B          | ~225,055 B               | **20.8×** |
| User txs per block                | ~92                | ~90                      | ~1×       |
| Total chain data (60 s)           | ~0.33 MB           | ~6.87 MB                 | **20.8×** |
| Sustained TPS (no errors)         | 200                | 200                      | 1×        |
| Sign latency (per tx)             | ~0.1 ms            | ~5–15 ms                 | ~100×     |
| Sender recovery                   | ecrecover          | registry lookup + verify | —         |
| TPS ceiling (block prop < 0.45 s) | _measure at scale_ | _measure at scale_       | —         |

Key takeaway: PQ throughput capacity is identical to secp256k1 at 200 TPS on this devnet —
the bottleneck is block bandwidth, not node CPU. Each PQ block carries 20.8× more bytes for
the same transaction count, which becomes the limiting factor at higher TPS.

## Operational Commands

```bash
# Stop all validators
bash bsc_cluster.sh stop

# Restart a single validator (e.g. index 0)
bash bsc_cluster.sh restart 0

# Wipe and restart everything
bash bsc_cluster.sh reset

# Tail validator 0 logs
tail -f .local/node0/bsc.log

# Check each validator's block height
for PORT in 8545 8547 8549 8551; do
  H=$(curl -s http://127.0.0.1:$PORT \
    -X POST -H "Content-Type: application/json" \
    -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}' \
    | jq -r '.result // "err"')
  printf "port=%d  block=%d\n" $PORT $((H))
done

# Check PQ registry for an address
ADDR="0xABCD...1234"
curl -s http://127.0.0.1:8545 \
  -X POST -H "Content-Type: application/json" \
  -d "{\"jsonrpc\":\"2.0\",\"method\":\"eth_call\",\"params\":[{\"to\":\"0x0000000000000000000000000000000000000070\",\"data\":\"${ADDR}\"},\"latest\"],\"id\":1}" \
  | jq -r '.result' | wc -c   # should be 2626 (= 1312 bytes hex + 2 for 0x prefix)
```

## Troubleshooting

| Symptom                                                | Cause                                 | Fix                                                                                        |
| ------------------------------------------------------ | ------------------------------------- | ------------------------------------------------------------------------------------------ |
| `is not an active PQ validator`                        | PQ registry cache not warmed          | Ensure geth built from `post_quantum_dev`; check `inject_pq_genesis.py` ran during reset   |
| `sender not registered` error in node log              | `pqRegistryBackend` nil or cache cold | Ensure geth was built from `post_quantum_dev`; restart node after registration tx confirms |
| `STARK attestation assembled` votes=0                  | BLS/PQ address mismatch in snapshot   | Rebuild geth — pq_vote_attestation.go must use PQVoteAddress not VoteAddress               |
| No `PQ vote produced` in logs                          | Missing `--pqvotekey` or wrong path   | Check `start_node()` in bsc_cluster.sh; verify `pq/privkey.bin` exists in node datadir     |
| txpq exits with `registration tx not mined within 60s` | Chain not producing blocks            | Check `bsc_cluster.sh reset` completed; check validator logs                               |
| `already registered with a different pubkey`           | Key file changed after first run      | Use same `-seed` value; or wipe devnet and restart                                         |
| All txpq sends fail with `nonce too low`               | Multiple workers sharing nonce state  | Reduce `-workers`; nonces are striped by worker ID                                         |
| Block timestamp drift > 500 ms                         | TPS ceiling hit                       | Record this `-workers` value as the ceiling data point                                     |
